# 内置软件开发 Skill

应用版本：2.1.0。Skill：software-development v1.0.0。日期：2026-10-24（北京时间）。

## 使用

进入开发工作空间，导入项目并配置支持工具调用的模型。「开发 Skill」默认选择「软件开发」，可点击「查看指引」。新建任务后，Agent 会在其系统上下文中收到 Skill 主文档，并可用 read_skill_resource 按技术栈加载补充资源。

示例任务：

- 分析项目结构、入口和运行方式，只读输出发现。
- 修复具体边界值错误，保留已有行为，执行项目原测试并报告结果。
- 完成指定接口或界面功能，覆盖关键失败路径。
- 审查开发文档与实现，按文件和行号报告有证据的问题。

每个任务的执行面板显示 Skill 名称、版本和已加载补充资源数量。切换选择只影响新任务；选择「不加载内置 Skill」时基础工具、审核、验证门槛继续生效。取消 Skill 不会取消这些后端约束。

## 资源与加载

- `backend/skills/catalog.json`：可用 Skill 的名称、版本、描述和参考资源路径。
- `backend/skills/software-development/SKILL.md`：开发工作流、完成证据、任务范围及资源选择。
- `references/javascript-node.md`：模块、异步处理、接口与 UI 边界、Node/npm 检查。
- `references/python.md`：Python 项目上下文、服务生命周期与当前执行能力边界。
- `references/code-review.md`：审查范围、证据、位置与影响，不把审查请求当作修改许可。

目录作为应用自身资源一起冻结打包，不从导入项目或任意磁盘路径注册、执行 Skill。read_skill_resource 只返回当前任务快照中列出的资源，没有执行脚本或访问凭据的能力。

## 持久化与追踪

启动任务时固定 Skill 主文档、参考资源和 SHA-256 摘要，保存在该任务的 `_skillSnapshot` 内部字段。主文档每轮都进入模型系统上下文；补充资源首次调用后也会随任务检查点持续保留，不因普通聊天历史裁剪丢失。未加载的资源不预先发送给模型。

会话 API 返回名称、版本、摘要和已加载资源，隐藏内部快照；完整导出记录包含任务快照及激活、资源加载事件，便于核对模型当时所用指引。版本更新只影响之后的新任务；重启或继续任务保持原内容。旧版本任务不自动追加入 Skill。

## 能力边界

Skill 是可复用的工作指引，没有新增终端权限、依赖安装、联网浏览、发布或账号操作。它不代表模型经过额外训练，也不保证所有任务都能完成。

文件工具可以读写多语言源码。当前执行白名单和行为测试完成门槛仍面向 Node/npm。Python 指引明确禁止虚构 pytest 结果、制造空 Node 用例或修改 npm 脚本绕过命令范围；缺少可用验证时应保存进度并请求帮助。Skill 不能绕过只读任务、逐项审核、项目文件边界或当前源码行为测试要求。

## 验证

Skill 按 skill-creator 的 quick_validate.py 检查通过。新增回归覆盖自动激活、模型请求上下文、按需参考读取、历史裁剪、重启与版本固定、关闭 Skill、错误 ID、路径限制、只读和审核边界及界面选择/预览。真实 Node 修复闭环也先加载 Skill 参考，再经历失败、纠错、测试通过与复核。

模型回复使用确定性样本，文件、子进程和浏览器操作实际执行；不构成真实厂商模型的成功率评测。打包验证会读取冻结目录的 Skill API，并对照后端自检中的摘要，确认安装包确实携带资源。
