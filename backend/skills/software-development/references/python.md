# Python

从 pyproject.toml、requirements 文件、项目入口和现有测试确认 Python 版本、框架、包结构与依赖约定。避免把导入成功等同于业务正确。修改异步服务时检查阻塞 I/O、任务取消、连接和文件关闭、异常映射及启动/关闭生命周期。

对于参数或接口改动，追踪路由、调用方、数据格式、持久化与旧数据兼容性。修复应覆盖出错条件及正常行为，不用宽泛 except 掩盖根因。测试需要隔离临时目录、外部请求和账号数据，避免测试污染用户实际数据。

## 执行与环境

run_command 使用 command="python"，args 为独立字符串数组，工作目录固定为导入项目根目录；无需激活虚拟环境。支持：

- `["-m", "pytest", "tests", "-q"]`；也可指定 `tests/test_calc.py::test_add`，或用 `-k`/`-m` 筛选。常用参数包括 `-v`、`-x`、`-s`、`--tb=short`、`--maxfail=1`，`-c` 和 `--ignore` 只接受项目内相对路径。
- `["-m", "unittest", "discover", "-s", "tests", "-p", "test_*.py", "-v"]`，无第三方测试框架时可使用项目已有 unittest 测试。
- `["-m", "py_compile", "src/calc.py"]` 检查指定 Python 文件的语法。
- `["scripts/check.py", "参数"]` 执行项目内已有脚本。

先查看项目依赖和测试配置，沿用实际测试入口，不虚构路径。解释器按 `.venv`、`venv`、应用启动环境中的 `SHUJIN_PROJECT_PYTHON`（绝对路径）、源码模式后端 Python / 打包模式 PATH 中本机 Python 的顺序选择。命令记录显示所选路径和来源。项目虚拟环境损坏或缺少 pytest 时明确报错，不改用其他环境掩盖问题；打包应用内置后端不作为项目 Python。需要用户准备环境时，说明具体解释器、依赖文件及缺失项，使用 request_user 或 fail_task 如实保留状态。

不支持 pip 安装、`python -c`、任意 `-m` 模块或 shell；不能更改脚本绕过命令范围。仅对可信项目按当前任务权限申请执行，只读任务不得运行项目代码。

## 验证闭环

先运行现有测试复现问题，读取真实失败输出，修改后再运行相关测试；命令排队或执行中须等待 command_result。pytest/unittest 的成功要求进程退出为 0 且至少一个用例实际通过；空测试、全跳过、xfail、仅收集和伪造控制台成功文本不能满足行为测试门槛。py_compile 和脚本只作辅助检查，不代替行为测试。不要创建无关 Node 测试或把未运行的检查标为通过。

检查沿用审核、超时、停止进程树、输出上限及去重规则；源码变化后旧结果失效，未变化的失败检查重试须指定 retry_id。当前源码的行为测试通过且其他检查无失败后执行 review_diff，再 finish_task；缺少环境、依赖或验证证据时说明阻塞，不宣称已验收完成。
