# 代码审查

从用户指定的变更、文档或入口界定范围，追踪实际调用路径和状态变化。优先找可复现的功能错误、数据覆盖、权限失效、异常恢复、资源泄漏及文档与实现不一致；风格偏好不应淹没具体缺陷。

每个问题给出准确文件与行号、触发条件、当前行为、影响及修复方向。证据不足的地方明确为待确认，避免把推测写成确定漏洞。若没有发现可操作问题，直接说明，同时写清验证范围。不要因为任务叫“审查”就自动修改源码。

只读分析任务不能执行项目代码；可从源码和现有证据审查并说明未运行检查。如果用户要求实际修复，应使用允许修改与验证的任务，再按当前审批执行。检查文档中的测试结论时区分样本、真实子进程、真实外部服务和历史构建证据。
