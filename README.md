# 筱竹书瑾 2.1.28

以软件开发 Agent 为核心的本地工作台。最左侧图标栏按“房子（Agent）→ 图书（小红书）”排列，收起项目侧栏后仍可切换。项目与会话保留在独立侧栏中，小红书供等待 Agent 任务时手动使用。启动默认进入 Agent 工作空间。后端使用 **Python + FastAPI + Uvicorn**，前端使用原生 HTML/CSS/JavaScript，Windows 桌面窗口使用 Electron。

开发页采用紧凑工作台样式：移除顶部介绍与导航区，侧栏开关并入 Agent 标题栏，模型与权限配置并入输入框，对话和源码分别滚动。视觉变量与布局原则见 [前端视觉约定](docs/FRONTEND_DESIGN.md)。

项目任务列表支持独立滚动，侧栏右边缘可左右拖动调整宽度，并记住调整结果。双击边缘恢复默认宽度；聚焦边缘后也可用左右方向键调整、Home 键复位。

任务状态明确区分已完成、执行失败、等待用户回答；代码/命令待审核继续使用原审核入口。只有 finish_task 通过既有验证门槛才能完成；request_user 必须给出具体问题，暂停模型调用，回答后继续同一任务；fail_task 交付原因与证据。模型接口错误、预算耗尽、持续空转计为失败，可显式重试并保留前次结果，不再统一显示“需要反馈”。

Agent 页面浏览栏保留网页缩小与放大浏览图标，工具栏不显示网页标题、关闭按钮或说明文字。点击任务对话空白或消息会收起页面栏，点击输入框保持页面浏览展开，点击“展开项目文件”可恢复原页面和浏览状态。未选择项目时可先输入任务草稿，选择左侧项目后发送，草稿继续保留。

工具失败返回分类及纠正建议，并将近期失败带入后续请求。相同成功读取最多两次，等价默认参数也计入；文件变化或源码修订后允许重读。同一失败操作两次后拦截原样重试；连续五次错误、三次重复拦截或十轮无新证据会停止本次尝试。重复计划、不推进分页的空搜索、重复结果不算新进展；相同源码与命令最多两次失败执行。原有每次 40 轮/120 工具总预算仍保留。人工重试会开启新尝试，审核后的自动继续不清空防循环记录。

输入框底部仅显示当前模型名与访问权限，点击后展开模型选择、配置或权限选项。权限提供只读分析、逐项审核、自动执行；仅对新任务生效，当前任务权限不会随界面设置改变。任务轨迹显示后端保存的实际权限、项目目录和模型数据发送地址；权限菜单可展开后端提供的目录、命令、联网及敏感配置范围。文件工具限制在导入项目内，检查进程以本机账号运行，文件和网络未隔离。详见 [权限与执行范围](docs/ACCESS_PERMISSIONS.md)。

执行中的会话在侧栏显示转圈标志，小红书模块隐藏完整项目与会话侧栏，仅在顶部紧凑显示运行中及最近 5 个已完成任务名；点击任务名可返回 Agent 会话。右侧通过“项目文件 / 任务轨迹 / 页面浏览”标签切换，计划、工具记录和命令授权显示在任务轨迹中。桌面版点击“页面浏览”中的“在工作台内打开官网”可在 Agent 右侧小窗手动浏览小红书，中间保留任务对话与输入框。右侧页面栏左边缘可左右拖动调宽并记忆，双击恢复默认宽度，也支持方向键与 Home 复位。官网默认缩放为 80%；“缩小”每次降低 10 个百分点，最低 50%，“重置”恢复 80%，导航和大小窗切换保留所选比例。点击“放大浏览”进入小红书模块的大窗。大小窗共用同一页面，切换时保留页面与滚动位置，Agent 任务继续在本地后端执行。

Agent 顶部显示当前会话任务名。侧栏悬停会话后可归档，归档保留对话、任务及执行记录，展开项目下的“已归档”可查看或恢复。运行中或有待审核事项的会话需先停止并处理审核；归档会话恢复后才能继续任务。

Python 负责 HTTP API、项目与模型配置、模型协议适配、Agent 循环、文件审核与恢复、子进程检查和任务记录。Electron 负责窗口、文件夹选择器及手动内嵌官网页面，通过私有进程通道与 Python 通信。

**2.1.19 基础开发规范**：`backend/BASE.md` 在每轮模型请求中自动加载，即使选择不使用 Skill 也保留。规定需求理解、定向调查、实现或审查、验证和证据交付。任务类型默认自动识别，审查默认只读；可手动选择只读或修改模式。重复读取相同范围会收到纠正反馈，多轮审查会收到收敛提醒。旧版未产生变更或命令的审查任务，继续时可自动纠正为只读。模型仍须实际调用工具并交付证据，规范本身不保证任意外部模型的质量。

**内嵌官网保留浏览状态，自动化采集继续停用。** 点击「在工作台内打开官网」后，由你在官方页面手动登录、浏览和回复。首次打开需要主动点击；切换模块及最小化只隐藏现有网页，返回时不重新加载。同一次软件运行期间保留浏览状态，官网自身的正常后台连接可能继续；按 Escape、清理登录数据或退出软件才销毁页面并关闭连接。不会检测登录、提取二维码、自动刷新、点击、滚动或采集消息。新内嵌会话与旧自动化会话分开，不导入旧 Cookie。官网自身仍会发出正常页面请求，内嵌环境仍可能被平台限制；已有告警不会因此撤销。

## 本地运行

需要 Python 3.10+；桌面开发和 Node 项目检查需要 Node.js 22.12+。PowerShell：

```powershell
python -m venv .venv
.\.venv\Scripts\python.exe -m pip install -r requirements-dev.lock.txt
npm ci
.\.venv\Scripts\python.exe -m backend
```

打开 <http://127.0.0.1:3000>。`npm start` 也会启动项目虚拟环境中的 Python。旧版 `.local/developer/` 数据路径与 AES-256-GCM 加密格式保持兼容。

桌面版通过隔离的 Electron WebContentsView 内嵌官网，官网中的新窗口链接复用当前内嵌页，不打开外部浏览器；站外链接被阻止。官网页面没有 Node 权限和工作台桥接。网页版仍通过普通外链打开官网，不绕过网站的框架嵌入限制。后端不依赖 Playwright；它仅用于隔离测试。旧 connect、login/refresh、recommendations、messages 接口继续返回 HTTP 410。

Linux/macOS 使用 `.venv/bin/python`；安装和构建依赖可使用 `requirements-dev.txt`，本次完整锁文件针对 Windows Python 3.10。桌面打包目前只验证 Windows x64。

功能完成情况与后续优先级见 [开发进度](docs/DEVELOPMENT_PROGRESS.md)，开发过程见 [2.1 系列开发记录](docs/DEVELOPMENT_2.1.md)，服务器下载发布与校验见 [下载服务部署](docs/DOWNLOAD_DEPLOYMENT.md)。

`npm run dist:win` 先用 PyInstaller 生成 Python 后端，再用 electron-builder 生成：

- `release/XiaozhuShujin-Setup-2.1.28-x64.exe`
- `release/XiaozhuShujin-2.1.28-x64-Portable.exe`

安装包内置用于启动应用的 Python 运行时、后端依赖和前端资源。Python 项目检查需要另外准备项目虚拟环境或本机 Python 及项目依赖；内置后端不充当项目解释器。桌面 Node 检查使用 Electron 自带运行时；项目 npm 脚本仍需要本机 Node.js/npm 和项目依赖。安装包尚未签名。

国内下载失败时，在 `npm ci` 前设置 `ELECTRON_MIRROR=https://npmmirror.com/mirrors/electron/`，构建工具可设置 `ELECTRON_BUILDER_BINARIES_MIRROR=https://npmmirror.com/mirrors/electron-builder-binaries/`。`SHUJIN_PYTHON` 可指定开发模式解释器，打包模式固定使用内置后端。

开发数据仍保存在 Electron 用户目录的 `developer/`。升级前退出旧客户端，建议备份原数据目录；旧版和新版不要同时写同一份配置。手动内嵌页面使用独立持久会话，重新打开时浏览器可按官网规则保留登录；启动不自动加载官网。点击「清理本软件登录数据」并确认后，清理本软件内嵌及旧会话，不影响系统浏览器。

## 开发 Agent

2.1.20 内置「软件开发 Skill v1.1.0」。新任务默认启用，根据目标和读写模式自动加载代码审查、问题分析、问题修复、功能开发或重构指引；JavaScript/Node 和 Python 指引继续按需读取，减少无关上下文。任务轨迹显示当前流程，记录版本、摘要和已加载资源；恢复沿用原快照，不随升级或追加反馈重新路由。旧任务没有 Skill 快照时不追加入新的指引。

Skill 不增加工具权限，不替代模型能力或实际测试。当前源码支持 Node/npm 和 Python 项目实际检查，未执行的检查不能标为已验证完成。详见 [内置 Skill 说明](docs/BUILTIN_SKILLS.md)。

进入「工作空间 / 开发 Agent」，导入项目，填写模型接口前缀、模型名和 API Key。支持 OpenAI Chat Completions、OpenAI Responses API 和 Anthropic Messages，模型必须支持工具调用。接口前缀例如 `https://api.openai.com/v1`，服务分别追加 `/chat/completions`、`/responses` 或 `/messages`；不要在 Base URL 中重复填写端点。

输入框随内容自动增高、删减后收缩，达到高度上限后内部滚动。可将图片直接 Ctrl+V 粘贴到输入框或拖入，预览、移除后与文本一起发送，也支持只发送图片。未选择项目时可先粘贴并保留图片草稿，选择项目后发送。每条消息最多 4 张 PNG/JPEG/WebP，单张不超过 5 MB、合计不超过 12 MB。图片需要所选模型支持视觉输入，选择 Responses 协议本身不代表模型具备视觉能力。

图片保存在本机会话数据目录，历史中可以点击放大；上下文压缩和重启继续任务时仍可读取原图。发送失败时保留当前文字与图片草稿。任务执行时，添加的图片会发送到任务绑定的模型接口。2.1.21 安装包已包含图文输入、动态高度和连接中断自动重试。

模型连接遇到网络传输错误时会自动重试，最多尝试 5 次，等待时间依次为 1、2、3、4 秒；仍无法连接时任务才会失败。用户停止任务会立即取消当前请求或重试等待。模型明确返回的鉴权、权限、限流和请求格式错误不会重试。

选择只读分析或代码修改与验证，写明目标和完成标准。修改和命令默认逐项审核，也可分别授权本次任务自动修改、执行检查。任务和读取的源码会发给所选模型服务；这不是离线模型。

Agent 保存计划、读取源码、提出修改、执行检查、根据失败纠错并复核差异。只有 `finish_task` 能完成任务。修改任务必须有当前源码的行为测试通过记录和测试后的最终复核；语法检查、模型文字、待审核变更、运行中命令、过期结果不能完成任务。

每个文件改动分别显示路径、原因、修改前后行数和按需加载的行级差异，新增和删除行有颜色区分；可逐项接受并应用或拒绝。拒绝保持原文件不变；应用前会检查文件是否仍与提案基线一致。已应用的修改可恢复到任务开始前内容；若应用后文件又被用户修改，恢复会停止并保留用户当前内容。

支持 `node --test [相对路径]`、`node --check 文件`、`npm test`、`npm run test|build|lint|typecheck|check`。内置 Node 报告器排除空测试文件；npm 脚本是否覆盖业务，仍须审查脚本和测试内容。

Python 检查使用 `run_command` 的 `command="python"`，参数逐项传入数组：

- `python -m pytest tests -q`，支持相对路径、`文件::用例`、`-k/-m` 筛选等常用参数。
- `python -m unittest discover -s tests -p test_*.py -v`。
- `python -m py_compile src/app.py` 和 `python scripts/check.py 参数` 用于辅助检查与脚本执行。

项目解释器依次选择导入目录的 `.venv`、`venv`、应用启动环境中的 `SHUJIN_PROJECT_PYTHON` 绝对路径、源码模式后端解释器 / 打包模式 PATH 中的本机 Python。命令审核和记录展示所选解释器。损坏的虚拟环境或缺失 pytest 会直接报错，不静默换环境；依赖由用户按项目说明预先安装，Agent 不运行 pip、任意 `-m` 模块、`-c` 或 shell。`SHUJIN_PROJECT_PYTHON` 与用于启动开发后端的 `SHUJIN_PYTHON` 分别配置。

pytest/unittest 必须退出成功并至少有一个用例实际通过，空测试、全跳过、xfail、仅收集、语法检查和脚本成功均不能满足行为测试门槛。Python 结果使用独立报告，不依赖控制台成功文本；每次执行隔离字节码缓存，避免修改后误测旧代码。测试通过后仍须复核当前差异才能完成。

源码审查采用流式 UTF-8 读取，支持超过 160 KB 的文件、超长单行与中文；每页最多 12,000 字符，返回 next_offset、hasMore、总长度及内容摘要。文件预览可点击继续读取。目录默认只加载当前层，每页 200 项，点击展开子目录或加载更多；模型可按 path 定位、按需递归分页。搜索支持大文件、限定文件或目录及续查游标，单次最多返回 60 个匹配，扫描约 200 万字符或 200 个文件后返回续查位置，不能把部分搜索当作全库无匹配。

常见依赖、构建产物、缓存、敏感名称及符号链接/目录联接自动排除，包含 node_modules、vendor、.venv、venv、dist、build、target、coverage 等；当前采用内置排除表，不解析项目 .gitignore。取消原 1,200 文件、6,000 条目、10 层及单文件 20 MB 的快照硬限制，快照哈希按块计算。只读审查允许按相关范围交付并说明覆盖范围；整文件替换仍限 160 KB，且必须先读全当前版本。最终复核返回真实 unified diff，超出展示上限则拒绝复核成功。

每个项目只允许一个执行或待审核任务。命令最长 120 秒，保留末尾 24,000 字符，超过 2 MB 终止。相同源码与参数默认复用记录；失败后显式指定命令 ID 才重试。停止终止进程树；重启将未知结果标为中断。恢复检查摘要，拒绝覆盖外部改动，新建文件不自动删除。每次继续最多 40 轮模型、120 次工具。

命令白名单不是操作系统沙箱。项目检查仍可执行本机代码，只应授权可信项目。API Key 加密保存，接口不返回原密钥；加密密钥另存于数据目录，需按本机账号权限保管。JSONL 记录可能含源码和输出，可从界面导出。
